# 网站发布

## 发布前置条件

用户已授权发布这些具体资源；Notion 人工审批完成；脚本 `approved` 或 Notion 连接工具已完成审批文档规定的当前内容核对。只持有 GitHub 协作者身份仍需要当前环境有已授权账号连接。连接缺失时完成草稿、检查和可审阅文件，说明需要连接的账号。

检查网站当前分支、未提交修改及部署设置。在可用的隔离工作目录完成本次编辑。读取相关目录规则，使用文件编辑工具加入批准的 `Resource`，保留已有内容及身份字段。

## 更新内容

1. 按照 [审批流程](review.md) 读取批准资源，将脚本导出结果或连接工具核对后的完整资源内容作为待发布数据。
2. 再次检查网站与 Notion 的名称、官网、ID 和 slug。已有资源按 slug、官网和名称匹配身份，并保留其网站原有 ID；Notion 原有编号单独保留。新增资源 ID 必须在两边都未使用。目标内容完全一致时，继续检查部署情况；出现冲突时停止该资源更新并确定原因。
3. 使用当前环境的文件编辑工具更新 `data/resources.ts`，字段直接来自批准数据。核实材料留在 Notion 正文，网站文件只包含 `Resource` 字段。
4. 核对修改范围：仅包含本次批准的资源，已有记录保持完整；中英文介绍、类别、费用、地区与官方链接一致。

网站现有 `npm run sync:notion` 会从所有 `Published=true` 的记录整体生成 `data/resources.ts`。执行该命令需要确认当前环境允许生成代码，并且已理解完整同步影响。发布前还需验证同步程序对实际 Notion 字段类型的处理：当前适配依据中的程序只读取 ID 的 rich_text 和 Featured 的 checkbox，数字 ID 会使用查询顺序生成编号，单选 TRUE 会生成 featured=false。因此，对 number ID 和 select Featured 的数据库使用文件编辑工具发布已批准内容；后续整体同步需要维护者完成字段适配和完整数据核对后执行。

## 构建与提交

在网站目录执行已有检查：

```sh
npm run build
```

读取 `package.json`，存在其他必要检查时执行。核对生成页面中包含目标资源名称和官网链接；使用页面文本或 DOM 检查中英文内容，按当前环境规则决定是否使用浏览器。

使用网站已有分支与 PR 规则提交。公开 PR 列出新增资源、公开来源、核实日期和通过的检查；Notion 审批链接、私人信息和内部评审记录保留在获授权的内部位置。创建 PR 后在内部审批记录中保存 PR URL；拥有发布授权与权限时完成现有合并、部署流程。需要人工合并或环境审批时，交付具体 PR 及剩余操作，不能宣称网站已经上线。

本地检查生成的 `out/`、依赖目录、凭据及 `work/` 不加入本次内容提交。仓库已经跟踪的生成文件按网站当前维护规则处理。

## 部署与搜索

读取现有网站托管配置，确认正式分支、部署目标和预览方式。沿用已配置的 Git 集成或部署命令。部署之前重新读取 Notion 批准结果：脚本流程确认内容校验值一致，连接工具流程逐字段核对审批草稿与当前内容；人工撤销批准或修改内容时停止发布。

部分网站工作目录包含 Cloudflare AI Search 同步功能。只有当前 `package.json` 存在相应命令时，才按照当前仓库 README 执行。网站页面发布成功后，在对应发布版本运行：

```sh
npm run sync:search
npm run check:search
```

`sync:search` 会更新生产搜索数据并删除已不在资源数组中的旧项目，所以执行目录必须包含完整的已发布数据，且部署版本与搜索同步版本一致。账号、权限或检查失败时，报告页面部署及搜索同步各自的实际状态。

## 完成验证

从正式网站读取页面或页面数据，验证新增条目的名称、分类、中英文内容和官方链接。存在语义搜索时，再检查搜索能够返回新增资源。记录生产部署 URL 或提交标识、Notion 页面与检查结果。

只有确认正式网站可访问相应内容后，报告已上线。仅创建 Notion 页面、导出 JSON、构建成功或创建 PR，都需要说明相应阶段。部署失败时保留当前修改与审批材料，修复问题后继续。
